# v0.1 Release Guide

## What this release is

v0.1 is the portfolio-quality release of the Quantitative Finance Research & Validation Platform's first specialization: **equity derivatives and volatility modeling**.

It consolidates the already-merged M1–M8 quantitative work and UI1–UI5 native Workbench. It does not add another model merely for breadth.

The release story is:

```text
Black-Scholes reference pricing
-> independent valuation + Greeks
-> dynamic Delta hedging
-> observed SPX evidence + implied volatility
-> Heston forward valuation
-> Heston calibration + identifiability evidence
-> predeclared held-out Black-Scholes vs Heston validation
-> measured performance engineering
-> native validation/model-risk Workbench
```

## Supported v0.1 distribution target

The supported release contract is deliberately narrower than "works everywhere":

- Python **3.12** source installation from the repository;
- optional native desktop UI with **PySide6 6.11.2**;
- clean non-editable installation and source-launch smoke verified on Ubuntu CI; and
- an **Ubuntu 24.04 x86_64** standalone `pyside6-deploy` artifact as the CI-verified packaged proof.

The release does **not** claim:

- macOS or Windows installer certification;
- code signing or notarization;
- an automatic update channel; or
- that the CI-produced Linux artifact is a universally supported end-user installer.

Those are separate distribution capabilities and require their own evidence.

## Install from a clean checkout

Use Python 3.12 or newer:

```bash
git clone https://github.com/abdullahkhan57721/quant-finance-platform.git
cd quant-finance-platform
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install ".[desktop]"
```

For development rather than release use, install `.[dev,desktop]` and follow `AGENTS.md`.

## Verify the release

Run the deterministic release check:

```bash
python scripts/v01_release_check.py
```

The check is intentionally network-free. It verifies:

- installed distribution version `0.1.0`;
- the committed M7 partition and headline held-out metrics;
- the M7 non-claims about temporal forecasting and Heston hedging;
- the committed M8 heavy-workload speedups and deterministic/statistical parity semantics; and
- the M8 decision that no C++ kernel is part of v0.1.

This verifies the **committed derived release evidence**. It does not pretend that the raw SPX source rows are redistributed by this repository.

## Launch the native Workbench

On the maintained headless Linux verification path:

QT_QPA_PLATFORM=offscreen python -m qf_platform.desktop.main --smoke-test

The native Workbench is downstream of the quantitative core. QML does not implement prices, Greeks, calibration, validation metrics, or performance measurements.

## Reviewer demo path

A useful first pass through the product is:

1. **Valuation & Sensitivity** — compare Black-Scholes analytic, CRR, and Monte Carlo valuation and inspect Greeks.
2. **Dynamic Hedging** — inspect model-generated Delta-hedging evidence, including rebalance frequency, volatility misspecification, and transaction costs.
3. **Market Evidence / Implied Volatility** — inspect the observation-to-normalization-to-inference boundary and smile/skew evidence.
4. **Heston Forward Valuation** — compare independent Fourier and Monte Carlo methods.
5. **Heston Calibration** — inspect multiple starts, residuals, rank, and conditioning rather than only optimizer success.
6. **Validation / Model Risk** — inspect training versus held-out Black-Scholes/Heston results and the bounded conclusion.
7. **Performance Evidence** — inspect the revision-pinned M8 before/after workloads and the measured no-C++ decision.

## Flagship M7 empirical result

The committed M7 study uses 14 selected SPX/SPXW contracts from **January 4, 2023** across two expiries. The partition is predeclared before fitting:

```text
10 training observations
4 held-out evaluation observations
```

Reference held-out evidence:

| Metric | Black-Scholes | Heston |
| --- | ---: | ---: |
| Price RMSE | 8.412 | 0.671 |
| Half-spread-standardized RMSE | 20.613 | 1.649 |
| Relative MAE | 8.27% | 0.66% |

Under this explicit same-date cross-sectional design, Heston materially improves held-out pricing metrics relative to the fairly fitted one-volatility Black-Scholes benchmark.

It does **not** establish:

- temporal out-of-sample forecasting skill;
- physical-measure forecasting skill;
- global/unique Heston parameter identification;
- historical trading profitability;
- universal Heston superiority; or
- Heston hedge superiority.

Authoritative evidence:

- `docs/models/m7_empirical_validation_and_model_risk.md`;
- `docs/evidence/m7_spx_bs_vs_heston_validation_reference.json`.

## Raw-market replay boundary

`scripts/m7_model_validation.py` is the authoritative path from the pinned raw artifact when the user has that artifact locally. Raw source rows are intentionally not redistributed by this repository.

The raw replay requires a local CSV whose Git blob matches the pinned source identity:

```bash
python scripts/m7_model_validation.py /path/to/pinned/data.csv \
  --retrieved-at <timezone-aware-ISO-8601-timestamp> \
  --spxw-european-pm \
  --output /tmp/m7-validation.json
```

The script performs no network retrieval and rejects a local CSV whose Git-blob identity does not match the pinned source.

This distinction is intentional:

```text
network-free release verification of committed derived evidence
!=
raw-source replay from a separately obtained pinned artifact
```

## M8 performance result

M8 profiled workloads frozen by M7 before selecting any optimization target. The committed same-run reference reports:

| Heavy workload | Baseline | Optimized | Speedup |
| --- | ---: | ---: | ---: |
| Heston Monte Carlo, 20k x 252 | 3.3673 s | 0.1230 s | 27.38x |
| 10-target / 3-start calibration | 2.2919 s | 0.4971 s | 4.61x |
| 14-target / 3-start calibration | 3.2752 s | 0.5454 s | 6.01x |
| Complete M7 validation study | 5.4136 s | 1.0819 s | 5.00x |

These hosted-runner timings are revision/environment-pinned descriptive evidence, not universal latency guarantees or CI thresholds.

Deterministic financial parity checks pass. Heston Monte Carlo parity is statistical because M8 intentionally changed the RNG implementation; equal integer seeds do not imply identical old/new random streams.

After the Python/NumPy and algorithmic improvements, a C++ kernel was **not justified for the v0.1 representative workloads**. This is a measured engineering decision, not an unfinished feature.

Authoritative evidence:

- `docs/models/m8_performance_engineering.md`;
- `docs/evidence/m8_performance_reference.json`.

## Release-quality verification

The release candidate must pass on its exact head:

```text
Core CI
+ Release Verification CI
+ Desktop CI
```

The Release Verification workflow proves a clean non-editable Python 3.12 installation, runs `scripts/v01_release_check.py`, and launches the installed Workbench through the headless source smoke path.

The existing Desktop workflow separately proves Qt/QML behavior and creates/launches the Ubuntu standalone artifact. M9 does not duplicate that packaging implementation.

## Release/tag order

The `v0.1.0` tag and GitHub release are created only after:

1. the M9 candidate passes exact-head validation;
2. the human/repository merge gate is passed;
3. M9 is squash-merged to `main`; and
4. required merged-`main` Core/Release/Desktop verification is green.

Only then is M9 repository-defined `MERGED` and the `v0.1.0` release/tag appropriate.

See `CHANGELOG.md` for the concise release notes.
