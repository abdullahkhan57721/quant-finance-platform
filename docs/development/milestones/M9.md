## Scope

M9 owns release consolidation and proof, including:

- one flagship reproducible study/narrative spanning the earned M1–M8 sequence;
- explicit data provenance and replay instructions for committed derived market evidence;
- clear validation/model-risk conclusions and non-claims;
- presentation of the M8 measured optimization result and the deliberate no-C++ decision;
- integration of the completed UI5 Workbench as the native product surface;
- clean installation and launch instructions that match tested repository behavior;
- release-oriented examples/documentation suitable for a technical portfolio review;
- a concrete v0.1 platform/distribution target based on evidence rather than aspiration;
- final repository-quality, reproducibility, and public-claim audit;
- release notes/changelog material and the v0.1 tag/release procedure when acceptance evidence is complete.

If the selected distribution target requires narrow packaging fixes or CI smoke coverage, those are in scope. Do not use release work as a reason to redesign scientific architecture.

## Non-goals

- new stochastic models merely for breadth;
- generic portfolio/VaR/XVA/rates infrastructure;
- Heston dynamic hedging unless separately justified by a future milestone;
- a generic plugin/model/backend registry;
- a C++ kernel for the current v0.1 workloads;
- claiming temporal forecasting, trading profitability, global Heston identification, or Heston hedge superiority;
- generic persisted-study/fork/document infrastructure unless a concrete chosen release workflow proves it necessary;
- multi-platform signing/notarization promises without corresponding tested release evidence.

## Architecture constraints

Preserve the current dependency direction:

```text
Qt Quick / QML
        ↓
curated PySide6 controller / item models
        ↓
frontend-neutral application + presentation
        ↓
public quantitative APIs + committed evidence
        ↓
production quantitative core
```

Release/presentation code must not become a second implementation of quantitative semantics.

Preserve these result boundaries in the public narrative:

```text
same-date held-out pricing evidence != temporal forecasting
calibration convergence != parameter identification
better held-out pricing != universal model validity
Heston pricing advantage != Heston hedge superiority
measured Python optimization != justification for a C++ backend
```

The M8 performance story is fixed unless new reproducible measurements on a materially changed workload justify reopening it:

```text
profile representative workloads
-> identify actual bottlenecks
-> optimize Python/algorithmic causes
-> 4.61x-27.38x pinned heavy-workload improvement
-> parity retained
-> C++ not justified for v0.1
```
