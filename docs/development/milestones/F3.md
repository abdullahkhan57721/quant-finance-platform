# F3 — Analyst Interoperability & Structured Exports

Status: **ACTIVE**  
Priority: **P1**

Work unit: Issue #59 / branch `f3-59-structured-exports`

## Purpose

Make authoritative quantitative results usable outside the application through finance-friendly structured artifacts, especially Excel/tabular workflows, without turning spreadsheets into a second quantitative engine.

## Central question

Can analysts/model validators export important platform evidence into auditable XLSX/CSV/JSON artifacts while preserving units, provenance, assumptions, and the distinction between calculated evidence and presentation?

## Dependencies

- F1 — Research API & Multi-Surface Interface Boundary (MERGED).

## Parallelization

After F1 merges, F3 may run in parallel with F2 and F4 if live overlap is safe.

F3 must not require unmerged F2/F4 behavior.

## Required orientation

Inspect:

- merged F1 result/evidence contracts;
- application analysis dataclasses;
- M2/M3/M4/M6/M7/M8 evidence structures;
- quantitative conventions and provenance semantics;
- packaging/dependency policy.

## Scope

1. Add a concrete export/reporting boundary downstream of authoritative immutable results.
2. Support finance-friendly artifacts:
   - XLSX workbooks;
   - CSV table extracts where a rectangular table is meaningful;
   - JSON for structured machine-readable evidence/provenance.
3. Cover the highest-value existing workflows with concrete adapters rather than one universal serializer. At minimum include:
   - valuation / Greeks comparison;
   - dynamic hedging evidence;
   - market/implied-volatility evidence;
   - Heston calibration/identifiability;
   - Black-Scholes vs Heston validation/model-risk evidence;
   - M8 performance evidence where included in the validation report.
4. Make the flagship validation workbook explicitly separate:
   - summary;
   - training metrics/contracts;
   - held-out metrics/contracts;
   - residuals;
   - calibrated parameters;
   - calibration starts/stability;
   - conditioning/identifiability;
   - assumptions/provenance/non-claims.
5. Keep spreadsheet files as rendered/exported evidence. Financial calculations remain in Python.
6. Add a documented programmatic export path usable by future UI clients.

A small shared table/report value representation may be extracted only if multiple concrete exporters demonstrate the same responsibility.

## Non-goals

- no Excel add-in;
- no VBA/macros;
- no spreadsheet-owned pricing/calibration formulas;
- no generic document/report engine;
- no PDF requirement in this milestone;
- no arbitrary object serialization;
- no Dash or notebook dependency;
- no semantic-version/release work.

## Architecture constraints

~~~text
typed quantitative result/evidence
            ↓
concrete export adapter
            ↓
XLSX / CSV / JSON presentation artifact
~~~

Protect:

~~~text
exported cell != quantitative authority
formatted display value != raw typed value
model residual != quote width != numerical error
training evidence != held-out evidence
provenance != decorative metadata
~~~

The exported artifact must make units/conventions/assumptions understandable without requiring the reader to infer them from formatting.

## Deliverables

Do not commit volatile generated binary workbooks unless a specific reviewed fixture is needed for test/portfolio purposes; prefer generation tests and documented examples.

## Validation

- canonical ./scripts/check_all;
- workbook structure/content tests;
- CSV/JSON schema/value tests;
- deterministic provenance/unit labeling checks;
- representative exported numbers must trace exactly to authoritative input result/evidence objects;
- no desktop or web dependency in the export layer.

## Acceptance criteria

- [ ] A Python consumer can export representative existing workflows to finance-friendly files.
- [ ] The flagship validation workbook clearly separates training, held-out evaluation, calibration/stability, conditioning, and model-risk limitations.
- [ ] Export adapters do not recalculate prices/Greeks/calibration/validation metrics.
- [ ] Structured outputs preserve enough provenance and conventions to audit where values came from.
- [ ] F4 can remain independent; F5 may later wire export actions into client surfaces after both milestones merge.
